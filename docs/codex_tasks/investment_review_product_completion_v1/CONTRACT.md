## Objective and completion semantics

### Fixed objective

从固定源基线构建一个可由普通用户实际使用的本地交易复盘候选系统，完成以下五部分：

1. 真实数据基础：安全追平并持续同步 portfolio 台账，建立决策/快照入口，并以简单、透明、可纠正的方式区分 `actual`、`estimated`、`unknown` 手续费；
2. 复盘流程串联：用一条稳定命令串联同步、费用投影、snapshot、episode、P2E-3/P2F facts-only 复盘和验证；
3. 用户界面：在现有 portfolio 网页提供复盘列表、时间线、决策理由、组合快照、手续费状态、证据抽屉和纠错保存；
4. 自动运行：交割单成功导入后在原事务之外触发幂等同步，提供启动补偿、单笔/周度/月度运行及健康状态；
5. 发布验收：在独立候选分支用真实只读来源完成端到端验证，形成可审计交付回执，但不自动推送、合并或部署。

### Definition of done

- 工程完成：五个阶段的代码、测试、playbook、API/UI、运行状态和回执均已提交；目标测试、全部 investment-review 测试、portfolio 回归、前端测试/构建及全仓测试均通过。
- 数据完成：执行时重新计算源台账和候选 sidecar 差额；一个成功同步 cutoff 下 `unsynced=0`，重复同步 `inserted=0` 且不产生内容漂移；源 portfolio SQLite 执行前后 SHA-256 完全相同。
- 复盘完成：至少一个来自正式只读来源的真实 episode 可在候选网页查看，并能生成可验证的 facts-only 复盘或明确的 partial/blocked 事实读数；不得通过放宽既有 P2E-3/P2F validator 来伪造 ready。缺失决策或历史快照必须作为缺口显示。
- 交互完成：用户可在候选网页完成“查看—补充决策—关联—纠正手续费或复盘结论—保存”，所有修订可追溯且不覆盖源台账或既有不可变产物。
- 运行完成：导入后触发、启动补偿、单笔/周度/月度运行和健康监控均有确定性测试；复盘失败不会回滚已成功提交的 portfolio 台账，并会显式显示滞后/失败。
- 候选发布完成：本地执行分支干净，所有 checkpoint 存在，交付回执列出测试、真实数据计数、源库哈希、已知缺口和人工发布下一步。生产合并、远端推送、部署和真人产品验收不属于本包完成声明。

## Checkpoint and resume protocol

1. 每次启动先验证 package、分支、源基线祖先关系、contract SHA、工作树和适用 instruction chain。setup commit 相对 `source_baseline` 只能包含本包两个文件。
2. 首次执行记录正式 source DB 哈希、schema、mapping hashes、当前行数和候选 sidecar 状态；不复制用户旧 sidecar。
3. 从最早未被 Git checkpoint 和验证证据共同证明的 phase 开始。不得仅凭 START_HERE 文本跳过 phase。
4. 每个 phase 只修改其允许路径；完成后运行 targeted validation、检查 diff、更新 START_HERE 的 state/phase/tests/blockers/next safe action，然后显式 stage 对应路径并创建规定 commit。
5. 每个 checkpoint 后要求 tracked tree clean。忽略的候选 DB/runtime artifacts必须在 checkpoint history 中列明，禁止误加入 Git。
6. 同步数据计数随时间变化时，以一个明确 cutoff 重新运行并记录；不得把准备时 22 条差额写成永久常量。
7. 复盘失败不得重做已成功的非幂等 portfolio 导入；只能重试 review-side idempotent sync/run。
8. 若恢复时存在未提交更改，只有当每个路径均属于 `next_phase`、diff 内部一致且动作可安全重复时才能继续；否则 hard stop。

At minimum: update `START_HERE.md`, run phase validation, inspect scope, stage explicit paths, create the named checkpoint commit, and require a clean checkpoint before the next phase. On resume, start from the earliest phase whose postconditions are not proven.

## Stop conditions

- contract/task ID/hash/source baseline/execution branch/instruction drift；setup commit 含包外文件；指定工作树之外出现重叠用户改动。
- reviewed mapping、source path、selected table、schema SHA 或 source identity 规则漂移；必须重新人工审核 mapping 时停止并提出一个明确问题。
- 任一步骤会写正式 portfolio DB、用户旧 sidecar、其他 worktree，或要求清理/覆盖/删除用户文件。
- 需要编造历史 decision、把 fee=0 当实际零、使用 future-known 信息、隐藏 missing/partial、降低既有 P2E-3/P2F/P2G/P2H validator，或输出 advice/score/diagnosis。
- 需要新依赖、凭据、外部 provider、OS scheduler、production process/port、push/PR/merge/deploy 等未授权动作。
- source DB 哈希意外变化、SQLite integrity 失败、source identity 重复/缺失、同步内容漂移、并发产生重复写、non-idempotent 操作完成状态不确定。
- 必需解释器、Node/Vitest/Vite、浏览器或 validator 不可用且无等价的既有项目验证方式。
- 同一根因经过三种实质不同方法仍失败。此时保存安全 checkpoint，在 START_HERE 写入 affected phase/criterion、证据、三次尝试和一个精确 unblock 问题，然后标 blocked。

历史人类理由缺失、旧 episode 的快照 partial、模型不可用本身不是 hard stop；它们应按契约显示 unknown/partial/facts-only。只有因此无法满足明确 criterion 且没有安全工程路径时才停止。

Always stop for contract/hash drift, unexpected overlapping changes, unresolved blocking decisions, unavailable required validators, destructive or external actions outside authority, uncertain non-idempotent state, or three materially different failed approaches to one root cause.
