## Checkpoint and resume protocol

1. 新聊天必须从专用工作树启动，完整读取 applicable `AGENTS.md`、冻结 `CONTRACT.md`、`START_HERE.md` 和该阶段点名的权威 files/skills。
2. 用 task-package validator 复核 contract canonical SHA。hash、task ID、branch 或 baseline 不一致即 hard stop。
3. 确认 source baseline 是 HEAD 祖先，package setup commit 只改两个 package 文件。任何其他初始 diff 都必须停止。
4. 从最早没有 postcondition 证据的 phase 开始。不能因 `START_HERE.md` 文本声称完成而跳过 Git commit 和验证 evidence。
5. 每个 phase 开始前，在 `START_HERE.md` 当前检查点记录精确计划修改路径；只修改 phase allowlist。
6. 每个 phase 结束时运行 phase validators、审计 scope、更新 readout 与 `START_HERE.md`，显式 stage 路径并创建命名 checkpoint；进入下一 phase 前工作树必须 clean。
7. P5 先完成 decoupling commit 和全部文件恢复演练，再按 Night、Bundle、old002837 三波更新 `START_HERE.md` 为 `blocked`，逐项列出当前波用户需要删除的绝对路径与恢复命令，并提交一个 clean arm-wave checkpoint；该 commit 是本波 `wave_parent_commit`，随后停止。每波完成后可在新聊天用同一 launch block 恢复。
8. 恢复 deletion checkpoint 时，先用 V-007 比较整个 status vector/name-status 与当前 wave manifest；不运行任何自动删除命令。集合和状态类型均一致才可 stage/commit/验证并进入下一波。
9. 最后一个 tracked seal commit 中，`START_HERE.md` 保持 `state=running` 且 next action 为执行外部 publication；此后不再更新 `START_HERE.md`、readout 或 validation 文件。CI、PR、merge、main SHA 和最终 `task_state=complete` 只进入 GitHub 与最终聊天 handoff，避免使 sealed SHA 自引用失效。不得为了把 `complete` 写回文件而制造新的未验证 HEAD。
10. 发布恢复先执行 V-014。命令超时或聊天中断不等于失败，也不授权重复创建 PR、重复 merge 或 force push。
11. 若一个根因经过三种实质不同方法仍失败，记录每种证据和共同根因，置为 blocked 并停止，不循环补丁。

最少动作始终为：更新 `START_HERE.md`、运行阶段验证、检查 scope、显式 stage、创建指定 checkpoint、确认 clean。恢复时从最早未被 postconditions 证明的 phase 开始。

## Stop conditions

- contract hash、task ID、branch、source baseline 或 package status 不匹配；
- 初始 setup commit 除两个 package 文件外还有改动；
- origin URL/repository slug 不匹配，或 `git ls-remote` 显示任何不属于 D-012 所选发布转换的远端 ref 漂移；发布前固定值和发布后允许值分别以 D-013、V-014、V-015 为准；
- 用户主工作树需要被切换、stash、reset、clean、提交或覆盖才能继续；
- 需要新网络研究数据、依赖安装、环境修改、secret、真实 reviewer 或人工决定才能伪装完成自动阶段；
- 需要创建新 global G ID、workflow_type、第二份 canonical state 或重复 blocker ledger；
- 002837 原文单位/口径无法核对，却有人试图把推断写成 fact；
- 用户当前 wave deletion 的整个 status vector/name-status 与精确 cleanup manifest 不一致，或涉及 protected denylist；
- 任何 Codex 批量/递归删除、direct push main、force-push、squash、rebase、amend、history rewrite、remote branch deletion 或清单外外部写入；
- 任一删除文件的 baseline ref/blob/hash/全量恢复失败，required validator 不可用，CI 为真实代码失败，PR 冲突，或 required event 的 exact-SHA CI run 数为 0；
- 远端 execution branch ahead/diverged、存在多个或不匹配 PR、merge 命令结果不明且远端查询无法确认；
- sealed candidate 后出现任何 tracked write；
- 试图偏离 D-012 固定的 exact-head guarded PR merge-commit 发布路径；
- 三种实质不同方法对同一根因失败。

始终为合同/hash 漂移、重叠脏改、未解决 blocking decision、越权 destructive/external action、非幂等状态不明或三次根因失败停止。停止时更新 `START_HERE.md` 为一个精确 blocker 和一个 next safe action，不扩大任务。
