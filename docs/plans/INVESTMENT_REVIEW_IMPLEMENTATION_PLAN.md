# 周期投资复盘产品 V1 实施计划

## 产品目标

用户打开一个报告中心，即可直接查看组合与单个标的的每日、每周和每月复盘。
报告以表现、持仓变化、风险、操作评价和后续交易建议为主体，单笔操作复盘只是
其中一部分。

没有决策记录时，系统根据操作序列、当时行情、仓位和组合背景自动推断交易动机，
并生成对应复盘。推断结果标记为 `system_inference`，但不因缺少原始决策记录而
停止分析。

每份报告可以直接给出个性化的买入、卖出、持有、加仓、减仓或退出建议，以及建议
仓位或仓位区间；建议与事实分开显示，并说明主要依据、风险和失效条件。

## V1 只建设这些能力

- 组合日报、周报、月报；
- 单标的日报、周报、月报；
- 无交易日的组合复盘；
- 收益、持仓、现金和风险变化；
- 无决策记录时的交易动机推断；
- 操作效果、合理性和可改进之处；
- 个性化交易建议与建议仓位；
- 一个简洁的报告页面、历史切换和自动生成。

## V1 不建设

- 新的 P2G/P2H 阶段；
- 行为画像、人格或心理诊断；
- 复杂评分、复杂风险模型和长期实验体系；
- 新的人工审批、哈希链、协议、回放或多层发布状态；
- 决策笔记管理平台；
- 券商连接、订单执行和自动交易；
- 对正式 portfolio SQLite 的任何写入；
- 与周期复盘无关的研究工作流功能。

现有 episode、事实包、行情、组合指标、API 和页面能力按需复用，不再把历史 P2
阶段作为普通报告的前置门。

`docs/playbooks/INVESTMENT_REVIEW_P2*.md` 继续作为历史实现参考；其中与当前

## 四个实施阶段

### 1. 真实日报样板

用一个真实交易日完成：

- 一份组合日报；
- 一份真实标的日报；
- 无决策记录时的动机推断；
- 操作评价；
- 明确的交易动作建议和建议仓位；
- 主要依据、风险与失效条件；
- 可直接阅读的页面展示。

通过条件：组合和标的数字能够核对，动机推断没有使用事后信息，建议使用报告生成
时能够获得的数据，用户认为报告具有实际决策价值。

### 2. 日报全面生成

- 每个交易日生成组合日报；
- 为当日持有或交易过的标的生成标的日报；
- 没有交易时仍生成组合状态、表现、风险和建议；
- 重复运行不产生重复报告。

通过条件：真实连续交易日稳定生成，缺少决策记录不会阻塞。

### 3. 周报与月报

- 按自然交易周和自然月汇总；
- 直接生成周期级组合和标的报告；
- 汇总贡献来源、仓位变化、操作序列和主要动机；
- 结合报告截止时点信息给出下一周期建议；
- 不把周报、月报实现成多份单笔报告的列表。

通过条件：六类报告都能从真实数据生成，并在同一页面切换。

### 4. 报告中心与自动运行

- 默认展示最新报告；
- 支持组合/标的、日/周/月和历史日期切换；
- 收盘后生成日报，周末生成周报，月末生成月报；
- 显示最后更新时间、失败状态和关键数据缺失；
- 允许补跑，但不自动执行报告中的交易建议。

通过条件：用户无需运行命令即可持续查看最新报告，失败可见并可补跑。

## 最小必要保护

只保留以下基础要求：

1. 正式 portfolio SQLite 始终只读；
2. 事实、系统推断、事后结果和交易建议分开显示；
3. 不用未来信息倒推当时动机；
4. 建议注明数据时间、主要依据、风险和失效条件；
5. 不保证收益，不把不确定判断写成确定事实；
6. 系统不连接券商、不自动下单。

普通报告不要求逐次人工审核、字节级回放、多阶段审批或新增修订链。只有源结构
变化、账务无法核对、时间边界冲突或可能写入受保护数据时，才进入深入检查。

## 产品完成标准

- 六类报告均可直接查看；
- 无交易和无决策记录都不会阻塞报告；
- 每个相关操作都有记录动机或系统推断动机；
- 每份报告都有明确复盘判断、交易动作建议和建议仓位；
- 页面以结论为主，技术审计信息默认隐藏；
- 自动生成稳定、可补跑且不修改源账本；
- 不输出保证收益或确定性承诺，不自动执行交易。
